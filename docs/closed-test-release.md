# Перша закрита збірка (профіль closed): інструкція крок за кроком

Для Windows, без технічних знань. Усі команди вводяться в **PowerShell** у папці проєкту
(`C:\Users\cocro\Downloads\cv-maker\cv-maker`). Слова після `>` у блоках нижче вводити не треба, це лише підказка.

## Що буде в цій збірці
- Профіль **closed**: замок експорту PDF діє (2 реклами підряд), реклами **тестові** (`testAds: true`), напис «Test Ad».
- **Pass і купівлі немає**: у вікні експорту нема кнопки «Kup Pass», ціни й екрана Pass (прапорець `billingAvailable` = false). Це зміниться в кроці 5b.
- Заглушок розробника немає, кнопки «Resetuj Pass i reklamy» немає.
- `versionCode` = **2**, `versionName` = **1.0** (файл `android/app/build.gradle`). Кожне нове завантаження в Google Play має мати **більший** versionCode. Для наступної збірки збільшіть його (3, 4, …); versionName можна лишати 1.0 або піднімати (1.0.1, 1.1).
- appId `com.savoj13.freecv` не змінюється.

## Крок 0. Іконка (перевірено)
Папка `assets/` містить нову зелену іконку: `icon-only.png` (зелений фон, документ із літерами CV), `icon-foreground.png`, `icon-background.png`. Android-іконки (`android/app/src/main/res/mipmap-*`) уже згенеровані з неї.

Якщо ви **змінюєте** файли в `assets/`, перегенеруйте іконки:

```
npm run android:icons
```

Команда потребує інтернету (завантажує інструмент `@capacitor/assets`). Після неї виконайте крок 1, щоб іконки потрапили в збірку. Для Play Console окремо потрібна іконка 512×512 PNG (це крок 5c, не тут).

## Крок 1. Зібрати веб-частину для профілю closed і перенести в Android
```
npm install
npm run android:sync:closed
```
Що це робить: перевіряє типи, збирає застосунок у режимі `closed`, копіює його в Android-проєкт і ставить нативні плагіни. Має закінчитись без червоних помилок.

## Крок 2. Перевірити, що в збірці немає заглушок
```
npm run check:closed
```
Очікуваний результат (усі рядки з ✓, код завершення 0):
```
✓ closed: інструментів розробника і заглушок у збірці немає
✓ closed: конфігурація монетизації відповідає профілю
✓ android: у файлах застосунку (assets/public) заглушок і кнопки розробника немає
```
Якщо є рядок із ✗, **не збирайте .aab**: скопіюйте повідомлення й надішліть мені.

Важливо: перевірку `npm run check:closed` запускайте **після** `npm run android:sync:closed`: вона дивиться на файли, які справді підуть у Android. Якщо між ними ви виконували `android:sync:dev`, повторіть крок 1.

(Команда `npm run check:prod` перевіряє обидва профілі й **зараз закінчується з помилкою для production**, бо там `testAds: true`. Це очікувано до фінальної збірки для магазину.)

## Крок 3. Зібрати підписаний .aab в Android Studio
1. Відкрийте проєкт: `npm run android:open` (відкриється Android Studio). Дочекайтесь, поки внизу закінчиться «Gradle sync» (смужка прогресу зникне). Якщо питає про оновлення Gradle чи плагіна, **відмовтесь** («Don't remind me»).
2. Меню **Build → Generate Signed App Bundle / APK…**
3. Виберіть **Android App Bundle** → **Next**.
4. **Key store path**: натисніть **Choose existing…** і виберіть `C:\Users\cocro\keystores\freecv.jks`.
5. Поля **Key store password**, **Key alias** (`key0`), **Key password**: введіть свої паролі. Нікуди їх не записуйте в проєкт. Можна лишити галочку «Remember passwords» вимкненою. → **Next**.
6. **Destination Folder**: залиште типову (`android\app\release`). У списку **Build Variants** виберіть **release** (не debug). → **Create**.
7. Дочекайтесь повідомлення «Generate Signed Bundle: bundle(s) generated successfully» і натисніть **locate**. Файл: `android\app\release\app-release.aab`.
8. Ключ `freecv.jks`, паролі й файли `.aab`/`.apk` **ніколи не додавайте в git**; вони вже виключені в `.gitignore`. Не переміщуйте й не перейменовуйте ключ і збережіть його резервну копію в окремому надійному місці: без нього оновлювати застосунок неможливо.

## Крок 4. Швидка перевірка .aab перед завантаженням
- Розмір файлу має бути розумним (кілька МБ, не 0).
- У Android Studio: **Build → Analyze APK…** і вибрати `app-release.aab`. Перевірте: у `AndroidManifest.xml` пакет `com.savoj13.freecv`, `versionCode` = 2. У Merged Manifest зверніть увагу, чи є дозвіл `com.google.android.gms.permission.AD_ID` (від бібліотеки реклам). Якщо його немає, повідомте мене: цей дозвіл пов'язаний із відповіддю про рекламний ідентифікатор (див. `docs/play-console.md`).
- Бажано встановити збірку на телефон і пройти експорт PDF: реклама тестова, кнопки Pass немає. Для .aab зручніше зібрати окремо debug (Run ▶ у Android Studio) із тим самим профілем (`android:sync:closed`).

## Крок 5. Завантаження в Google Play (коли акаунт готовий)
1. Play Console → ваш застосунок → **Testing → Closed testing → Create new release**.
2. Увімкніть **Play App Signing** (Google запропонує; ваш `freecv.jks` буде ключем завантаження).
3. Завантажте `app-release.aab`, у «Release notes» напишіть кількома словами, що змінилося.
4. Додайте список тестувальників (e-mail-список) і збережіть. Відповіді для анкет Console: `docs/play-console.md`.
5. **Умова Google для нових особистих акаунтів:** закритий тест має мати **не менше 12 тестувальників**, які залишаються підписаними **безперервно 14 днів**; 14 днів рахуються **від запуску тесту** (коли ці 12 уже підписалися), а не від створення акаунта. Лише після цього можна просити доступ до production. Перевірте актуальну вимогу в довідці Play Console, правила змінюються.

## Часті проблеми
- **«Gradle sync failed»**: закрийте Android Studio, у PowerShell виконайте `npm run android:sync:closed`, відкрийте знову.
- **Паролі не підходять**: перевірте розкладку клавіатури і регістр; alias має бути саме `key0`.
- **Play Console каже, що versionCode вже використано**: збільшіть `versionCode` у `android/app/build.gradle` і зберіть заново.
- **У застосунку не видно реклами**: у closed вона тестова й з'являється лише з інтернетом; перша реклама може завантажуватись кілька секунд.
